# 失败模式与降级处置

> 本文件按需加载，为评估流程中可能遇到的异常情况提供处置方案。

## 失败模式一览

| 编号 | 场景 | 严重程度 | 处置策略 |
|---|---|---|---|
| F01 | MCP 授权失败（401） | 阻断 | 停止采集，输出 Token 配置诊断，不出报告 |
| F02 | MCP 限流（429） | 降级 | 降低请求频率，已获数据照常评估，缺失项标【待采集】 |
| F03 | order-list 返回空 | 阻断 | 提示账号无消费记录，降级输出空白评估说明 |
| F04 | 营养数据匹配失败 | 降级 | 该餐品营养项标【待采集】，不影响其他订单评估 |
| F05 | 积分折现参数缺失 | 降级 | 用历史订单反推月均，折现率取默认值 8% 并标注假设 |
| F06 | calculate-price 限流 | 降级 | 退化用 query-meals 的挂牌价，标【基准价来源：菜单挂牌价】 |
| F07 | 报告数字勾稽不平 | 修正 | 运行 valuation_check.py 定位差异行，修正后重出 |
| F08 | 积分商城数据为空 | 降级 | 变现单价取默认值 ¥0.008/分，标注【默认估值】 |
| F09 | 优惠券数据为空 | 降级 | 优惠资产章节标【本评估区间无优惠券记录】 |
| F10 | MCP 服务不可达 | 阻断 | 提示网络问题或服务维护，建议稍后重试 |

## 降级输出规范

当数据不完整时，报告仍可出具，但必须：

1. **标注数据覆盖率**：在报告开头注明"本次评估数据覆盖率 XX%"
2. **缺失项标识**：所有缺失数据项用【待采集：原因】标注
3. **评估结论限定**：如关键数据缺失超过 30%，评估结论标注"因数据不完整，评估结论仅供参考"
4. **不编造数据**：任何情况下不得用编造的数据填充缺失项

## 阻断 vs 降级判断标准

- **阻断**：核心数据源（MCP 连接、授权、订单数据）不可用，无法完成评估
- **降级**：非核心数据源（营养、商城、部分优惠券）不可用，可基于已有数据出报告

## 诊断输出模板

### MCP 授权失败诊断

```
【MCP 接入诊断】
状态：授权失败（HTTP 401）
原因：MCP Token 无效或已过期
处置：
1. 前往 open.mcd.cn 重新获取 Token
2. 在 WorkBuddy 连接器配置中更新 Authorization Bearer Token
3. 重新触发评估
```

### 数据覆盖率不足提示

```
【数据覆盖率提示】
本次评估数据覆盖率：65%
缺失项：
- 营养数据：3 个餐品未匹配到营养信息（【待采集】）
- 积分商城：接口暂不可用，变现单价取默认值（【默认估值】）
评估结论因数据不完整，仅供参考。
```
